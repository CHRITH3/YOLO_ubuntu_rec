================================================================================
                        数据格式详解
================================================================================

【原始输出格式】[1, 56, 8400]

理解方式: 8400个候选框,每个框56个数字

每个候选框的56个数字:
┌─────────────────────────────────────┐
│ 索引  │ 含义        │ 数量           │
├───────┼────────────┼───────────────┤
│ 0-3   │ bbox       │ 4 (cx,cy,w,h) │
│ 4     │ confidence │ 1              │
│ 5-7   │ keypoint 0 │ 3 (x,y,vis)   │  ← 鼻子
│ 8-10  │ keypoint 1 │ 3 (x,y,vis)   │  ← 左眼
│ 11-13 │ keypoint 2 │ 3 (x,y,vis)   │  ← 右眼
│ ...   │ ...        │ ...            │
│ 53-55 │ keypoint 16│ 3 (x,y,vis)   │  ← 右脚踝
└─────────────────────────────────────┘

总计: 4 + 1 + 17*3 = 56


【关键点坐标格式】

在640x640的模型输出中:
    x: 0 ~ 640  (横坐标)
    y: 0 ~ 640  (纵坐标)
    vis: 0 ~ 1  (可见性/置信度)

需要转换到原图640x400:
    new_x = (x - pad_w) / scale
    new_y = (y - pad_h) / scale


【边界框格式】

YOLO输出 (中心点格式):
    cx: 中心x
    cy: 中心y
    w:  宽度
    h:  高度

转换为OpenCV格式 (左上角格式):
    x1 = cx - w/2  (左上角x)
    y1 = cy - h/2  (左上角y)
    cv::Rect(x1, y1, w, h)

================================================================================
                        常见问题解答
================================================================================

Q1: 为什么要转RGB?
A: OpenCV读取是BGR格式,但YOLO训练用的是RGB,必须转换!

Q2: 为什么要归一化?
A: 模型训练时图像值在[0,1],推理时也必须一致!

Q3: 8400从哪来的?
A: YOLOv8在三个尺度检测: 80x80 + 40x40 + 20x20 = 8400个网格点

Q4: 为什么需要NMS?
A: 一个人可能在多个网格被检测到,NMS保留最好的一个!

Q5: 置信度设多少合适?
A: 0.5是经验值,太低误检多,太高漏检多,可根据场景调整!
