   □ cv::resize() - 图像缩放

   □ cv::cvtColor() - 颜色空间转换
     - BGR -> RGB：cv::COLOR_BGR2RGB（YOLO需要）
     - BGR -> 灰度：cv::COLOR_BGR2GRAY
     - BGR -> HSV：cv::COLOR_BGR2HSV

   □ ROI（感兴趣区域）操作
     - cv::Rect roi(x, y, width, height)
     - cv::Mat roiImg = img(roi)  // 浅拷贝
     - cv::Mat roiCopy = img(roi).clone()  // 深拷贝

□ 4. 绘图功能（可视化检测结果）
   □ cv::rectangle() - 绘制矩形（人体框）
   □ cv::circle() - 绘制圆形（关键点）
   □ cv::line() - 绘制线条（骨架连接）
   □ cv::putText() - 添加文字（置信度标注）
   □ cv::Scalar(B, G, R) - BGR颜色顺序
   □ 线宽参数：正数=轮廓，-1=填充

三、关键知识点强化
================================================================================

⚠️ 1. BGR vs RGB（非常重要！）
   - OpenCV默认使用BGR顺序（不是RGB！）
   - 红色 = cv::Scalar(0, 0, 255)  // BGR
   - 蓝色 = cv::Scalar(255, 0, 0)  // BGR
   - 绿色 = cv::Scalar(0, 255, 0)  // BGR
   - YOLO模型需要RGB，所以要转换：cvtColor(img, rgb, COLOR_BGR2RGB)

⚠️ 2. 浅拷贝陷阱
   - cv::Mat img2 = img1;           // 浅拷贝，共享内存
   - cv::Mat img3 = img1.clone();   // 深拷贝，独立内存
   - ROI也是浅拷贝：img(roi) 修改会影响原图

⚠️ 3. 坐标系统
   - 图像坐标系：左上角为原点(0,0)
   - X轴向右，Y轴向下
   - cv::Point(x, y) = (列, 行)
   - 访问像素：img.at<type>(row, col) = img.at<type>(y, x)

⚠️ 4. Letterbox预处理的重要性
   - YOLO要求输入640×640，但摄像头图像可能是任意尺寸
   - 直接resize会导致图像变形
   - Letterbox：先等比例缩放，再填充到640×640
   - 保持宽高比，避免检测精度下降

================================================================================
五、常见问题解答
================================================================================

Q1: 为什么OpenCV用BGR而不是RGB？
A1: 历史原因。早期的相机和图像处理硬件使用BGR格式。OpenCV为了兼容性
    保留了这个传统。但深度学习模型（如YOLO）通常期望RGB输入，所以需要
    转换。

Q2: 什么时候用浅拷贝，什么时候用深拷贝？
A2: - 浅拷贝（=赋值）：当你只是想创建一个别名，节省内存
    - 深拷贝（.clone()）：当你需要独立修改数据，不影响原图

Q3: cv::waitKey(1) 和 cv::waitKey(0) 有什么区别？
A3: - waitKey(0)：无限等待，直到按下任意键
    - waitKey(1)：等待1毫秒，用于视频流实时显示
    - waitKey(30)：等待30ms，用于播放视频（约33fps）

Q4: 如何理解Letterbox预处理？
A4: 想象你要把一张照片放进640×640的相框：
    - 方法1（直接resize）：拉伸变形，图像失真
    - 方法2（Letterbox）：等比例缩小，空白处填充灰色，保持比例

Q5: 为什么要归一化到[0,1]？
A5: 神经网络训练时使用[0,1]范围的数据，可以加快收敛速度。如果输入
    [0,255]，梯度可能过大导致训练不稳定。
