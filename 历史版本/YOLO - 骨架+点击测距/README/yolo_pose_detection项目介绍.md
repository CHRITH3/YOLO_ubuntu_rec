1. 识别出你的身体
2. 找到你的关键部位（头、手、脚等）

## 🧩 项目的核心思路（分三个阶段）

### **阶段 1：让电脑学会"认人"**

这个项目用了一个叫 **YOLO** 的技术（读作"哟喽"）。

**什么是 YOLO？**
- YOLO 是 "You Only Look Once" 的缩写（"你只需要看一眼"）
- 这是一个已经训练好的"聪明大脑"
- 它已经看过几百万张人体照片，学会了识别人的姿势

**YOLO 能做什么？**
- 输入：一张照片
- 输出：17 个关键点的位置
  ```
  0: 鼻子      5: 左肩膀    9: 左手腕     13: 左膝盖
  1: 左眼      6: 右肩膀    10: 右手腕    14: 右膝盖
  2: 右眼      7: 左手肘    11: 左髋部    15: 左脚踝
  3: 左耳      8: 右手肘    12: 右髋部    16: 右脚踝
  4: 右耳
  ```

**就像画"连连看"游戏**：
- YOLO 在图片上标出 17 个点
- 把这些点连起来，就是一个"火柴人"骨架

---

### **阶段 2：知道"位置"在哪里**

YOLO 给出的只是**平面坐标**（2D）：
- 例如："鼻子在图片的 (320, 200) 这个像素位置"
- 就像在纸上画画，只有 X 和 Y 两个方向

但我们还想知道**深度**（3D）：
- 这个人离摄像头多远？
- 他的手是伸向前还是后？

这就需要**双目相机**！

**什么是双目相机？**
- 就像人的两只眼睛
- 两个摄像头从不同角度拍照
- 通过比较两张照片的差异，计算出"深度"（距离）

**类比：你怎么知道东西远近？**
- 闭上一只眼睛，试着抓桌上的杯子 → 很难！
- 用两只眼睛 → 轻松判断距离
- 双目相机的原理和人眼一样

---

### **阶段 3：把 2D 坐标变成 3D 坐标**

现在我们有两个信息：
1. YOLO 说："鼻子在图片的 (320, 200) 位置"
2. 深度图说："这个位置的物体距离摄像头 2.3 米"

用一个数学公式，就能算出鼻子在**真实世界**中的 3D 坐标：

```
X = (像素X - 图片中心X) × 深度 / 焦距
Y = (像素Y - 图片中心Y) × 深度 / 焦距
Z = 深度
```

**类比：用相机拍照片**
- 你拍了一个人，照片上他的头在照片正中间
- 但照片是平面的，不知道他离你多远
- 如果你知道"他离你 3 米"，就能推算出他真实的位置

## 🛠️ 用到的关键技术

让我们把项目拆解成一个个技术模块：

### **1. YOLO（姿态检测的"大脑"）**

**是什么？**
- 一个深度学习模型（就是"人工智能"）
- 训练过程：给它看几百万张标注好的照片，让它学习人体的样子
- 训练好后，它就能在新照片中找出人

**为什么选 YOLO？**
- **快**：一张照片只需要 50 毫秒就能处理完（比眨眼还快）
- **准**：能检测出 17 个关键点
- **轻**：模型文件只有 6MB（最小版本）

**版本选择**：
- 项目用的是 **YOLOv8n-pose**
  - `v8` = 第 8 代（最新）
  - `n` = nano（超小型号，速度最快）
  - `pose` = 专门用于姿态检测

---

### **2. ONNX Runtime（运行 YOLO 的"引擎"）**

**问题**：YOLO 是用 Python 训练的，但这个项目要用 C++ 编写（为了速度更快）

**解决方案**：
- 把 YOLO 模型转换成 **ONNX 格式**（一种通用格式）
- 用 **ONNX Runtime** 来运行这个模型

**类比**：
- YOLO 模型 = 一个游戏光盘
- ONNX Runtime = 游戏机
- 不管你的游戏机是 PlayStation 还是 Xbox，只要支持这个格式的光盘就能玩

---

### **3. OpenCV（图像处理工具箱）**

**是什么？**
- OpenCV = Open Computer Vision（开源计算机视觉库）
- 就像 Photoshop，但是是给程序员用的

**在这个项目中干什么？**
1. **读取摄像头**：从双目相机获取图片
2. **图像预处理**：
   - 调整大小（把 640×400 的照片变成 640×640）
   - 颜色转换（从 BGR 变成 RGB）
   - 归一化（把像素值从 0-255 变成 0-1）
3. **画骨架**：在图片上画圈圈和线条
4. **显示窗口**：把结果显示在屏幕上

---

### **4. IMSEE SDK（双目相机的"驱动程序"）**

**是什么？**
- IMSEE 是一个品牌的双目相机
- SDK = Software Development Kit（软件开发工具包）
- 就是厂商提供的"说明书 + 工具"，告诉你怎么用他们的硬件

**提供什么功能？**
1. 获取左右两个摄像头的图片
2. 自动计算深度图
3. 提供相机参数（焦距、图片中心点等）

---

### **5. CMake（自动化编译工具）**

**为什么需要它？**
- 这个项目有很多 `.cpp` 文件
- 需要链接很多库（OpenCV、ONNX Runtime 等）
- 手动编译太麻烦，容易出错

**CMake 做什么？**
- 你写一个配置文件（`CMakeLists.txt`）
- CMake 自动生成编译命令
- 一键编译整个项目

**类比**：
- 传统方式 = 手动做饭（切菜、炒菜、调味每一步都要自己来）
- CMake = 半自动厨房（你只需要告诉它做什么菜，它自动帮你完成）

## 🧮 关键算法详解（用大白话）

### **算法 1：Letterbox Resize（保持比例缩放）**

**问题**：
- 摄像头照片是 640×400（宽×高）
- YOLO 需要 640×640 的正方形图片
- 如果直接拉伸，人会变形（胖子变瘦子，或瘦子变胖子）

**解决方案**：
1. 按比例缩放到 640×400（宽度已经是 640，高度保持 400）
2. 上下各加 120 像素的黑边，变成 640×640
3. 就像在信纸上贴照片，照片不够大就留白边

---

### **算法 2：NMS（非极大值抑制）**

**问题**：
- YOLO 可能在同一个人身上画了 3 个框
- 需要只保留最好的那个框

**解决方案**：
1. 按置信度排序（最自信的排第一）
2. 保留第一个框
3. 把和第一个框重叠太多的其他框都删掉（重叠度 > 45%）
4. 重复，直到处理完所有框

**类比**：
- 你在淘宝搜"手机壳"
- 出现了 10 个几乎一样的商品（不同卖家）
- NMS 就是帮你去重，只留下独特的商品

---

### **算法 3：3D 投影（相机针孔模型）**

**原理**：
- 相机就像一个"针孔成像"装置
- 真实世界中的 3D 点，通过针孔投影到平面上

**公式推导**（简化版）：
```
已知：
- 图片上的点：(u, v) = (320, 200)
- 深度值：Z = 2300mm（2.3 米）
- 相机焦距：fx = 374.5, fy = 374.5
- 图片中心：cx = 318.8, cy = 197.4

计算：
X = (u - cx) × Z / fx = (320 - 318.8) × 2300 / 374.5 = 7.4mm
Y = (v - cy) × Z / fy = (200 - 197.4) × 2300 / 374.5 = 16.0mm
Z = 2300mm

结果：这个点在真实世界中的坐标是 (7.4, 16.0, 2300) 毫米
```

## 🤔 常见问题（小白版）

### **Q1：为什么需要深度摄像头？普通摄像头不行吗？**
A：普通摄像头只能得到 2D 平面坐标，就像看一张照片，分不清东西的远近。深度摄像头像人的两只眼睛，能判断距离。

### **Q2：YOLO 是怎么训练出来的？**
A：研究人员给 YOLO "看"了几百万张标注好的照片（每张照片都人工标出了 17 个关键点的位置）。YOLO 通过不断"做题 + 对答案"，学会了识别人体。

### **Q3：为什么有时候检测不准？**
A：
- 光线太暗 → 看不清
- 遮挡太多 → 只看到半个身体
- 距离太远 → 人太小了
- 姿势罕见 → YOLO 没见过这种姿势

### **Q4：能实时运行吗？会卡吗？**
A：
- 用 nano 模型在普通电脑上能跑到 15-20 FPS（每秒 15-20 帧）
- 人眼觉得流畅的标准是 24 FPS
- 所以略微有点卡，但基本能用
- 如果用 GPU 加速，能跑到 50+ FPS（非常流畅）

### **Q5：这个项目可以用来做什么？**
A：
- 健身 APP（检测深蹲、俯卧撑动作是否标准）
- 体感游戏（像 Switch 健身环）
- 跌倒检测（监护老人安全）
- 动作捕捉（制作动画、电影特效）
- 虚拟试衣（测量身材尺寸）

### **Q6：为什么用 C++ 而不是 Python？**
A：
- Python 更容易学，但运行速度慢
- C++ 运行速度快（快 10-100 倍）
- 实时视频处理需要速度，所以选 C++

### **Q7：我能修改代码让它识别其他东西吗（比如猫、狗）？**
A：可以！但需要：
1. 找到或训练一个识别猫/狗的 YOLO 模型
2. 修改关键点定义（猫有不同的关键点）
3. 重新标注骨架连接方式

### **Q8：为什么是 17 个关键点，不是更多？**
A：这是 COCO 数据集的标准。17 个点已经足够描述人体的基本姿态。如果需要更精细的检测（比如手指），需要用专门的手部检测模型（可能有 21 个手指关键点）。

### **Q9：检测速度和精度能兼得吗？**
A：这是一个权衡：
- 快速模型（YOLOv8n）：15-20 FPS，精度 85%
- 精确模型（YOLOv8x）：5-8 FPS，精度 92%
- 需要根据应用场景选择：游戏需要快，医学分析需要准

### **Q10：这个项目能在我的笔记本电脑上运行吗？**
A：取决于你的配置：
- **最低要求**：Intel i5 CPU，8GB RAM，普通 USB 摄像头 → 可以跑，但可能只有 10 FPS
- **推荐配置**：Intel i7 CPU，16GB RAM，IMSEE 双目相机 → 流畅运行 15-20 FPS
- **最佳配置**：带 NVIDIA GPU，CUDA 加速 → 50+ FPS

### **性能指标**

| 模型 | 大小 | 参数量 | FPS (CPU) | FPS (GPU) | 推理时间 | mAP |
|------|------|--------|-----------|-----------|----------|-----|
| YOLOv8n-pose | 6 MB | 3.3M | 15-20 | 50+ | 50-70ms | 50.4 |
| YOLOv8s-pose | 12 MB | 11.6M | 10-15 | 40+ | 80ms | 60.0 |
| YOLOv8m-pose | 26 MB | 26.4M | 6-10 | 30+ | 120ms | 65.0 |
| YOLOv8l-pose | 52 MB | 44.4M | 3-5 | 20+ | 200ms | 67.6 |
| YOLOv8x-pose | 98 MB | 69.4M | 1-3 | 15+ | 350ms | 69.4 |

**指标说明**：
- **大小**：模型文件的硬盘空间
- **参数量**：模型的复杂度（M = 百万）
- **FPS**：每秒处理帧数（越高越流畅）
- **推理时间**：处理一张图片的时间（越低越好）
- **mAP**：检测精度（Mean Average Precision，越高越准确）
