# 20260212 稳定性优化说明

> #  1.哪些情况会被判定为unknown姿态？
> # 2.现在人体坐标系的3D盒子框架老是跳动，推测原因是双目相机的性能问题，深度图数据跳动比较大，有没有办法可以让盒子再稳定一些？
> # 3.3种基本人体姿态的判断也不太稳定，尤其是pike姿势的识别不准，怎么优化？

## 1. Unknown 会在这些情况出现（按代码）

- 默认就是 Unknown：PostureMetrics.label 初始化为 "Unknown"，见 get_pose_indemind_left.cpp:178。
- 根本没进入姿态计算：只有 tracked_pose_index >= 0 才会调用 ComputePostureMetrics，否则保持默认值，见 get_pose_indemind_left.cpp:883、get_pose_indemind_left.cpp:885。
- 跟踪目标选不出来：tracked_pose_index 只在 bed_ready 且有 pelvis_valid 时选取，见 get_pose_indemind_left.cpp:842、get_pose_indemind_left.cpp:845。
- 骨盆点无效：髋点要 confidence > 0.5 且有有效深度才算有效，见 get_pose_indemind_left.cpp:798、get_pose_indemind_left.cpp:803。
- 躯干关键点不全：lh/rh/ls/rs 有任一缺失就直接返回（仍是 Unknown），见 get_pose_indemind_left.cpp:232。
- 左右腿角度都算不出来：left_valid/right_valid 都是 false（关键点无效或向量长度太小），见 get_pose_indemind_left.cpp:254、get_pose_indemind_left.cpp:263、get_pose_indemind_left.cpp:202。
- 左右腿分类冲突：两侧都有效但 left_label != right_label 时不赋值，仍保持 Unknown，见 get_pose_indemind_left.cpp:282、get_pose_indemind_left.cpp:285。

## 2. 3D 盒子跳动不一定只是双目性能，代码里还有几个明显抖动源

- 取帧逻辑和注释不一致：现在取的是 queue.front()（旧帧）再清空队列，不是“最新帧”，见 get_pose_indemind_left.cpp:639、get_pose_indemind_left.cpp:640、get_pose_indemind_left.cpp:648、get_pose_indemind_left.cpp:649。
- RGB/Depth 没做时间同步：回调给了 time，但深度回调里被丢弃，见 get_pose_indemind_left.cpp:566、get_pose_indemind_left.cpp:567。
- 盒子姿态和尺寸全是逐帧原始值：骨盆、轴向、torso_width/height 没有时间滤波，见 get_pose_indemind_left.cpp:864、get_pose_indemind_left.cpp:865、get_pose_indemind_left.cpp:1001、get_pose_indemind_left.cpp:1031。
- 可做的稳定化（优先级高）：
- 把图像/深度队列改成“取最新+按时间最近匹配”。
- 对 pelvis_cam、R_body_cam、torso_width/height 做 EMA/限速（每帧最大变化量）。
- 对 body frame 轴做“符号连续性约束”（避免轴翻转）。
- 深度采样加强：RobustDepthMedianU16 的窗口可适当加大，或加短时中值；当前只做空间中值，见 get_pose_indemind_left.cpp:775、app/depth_utils.cpp:6。
- 你已有可复用 EMA 实现（EMA3），可直接借到 body box 链路，见 app/depth_region.h:548。

## 3. Pike 不稳的优化方向（当前规则太硬）

- 当前分类只有两个硬阈值（135/135），没有滞回和时间平滑，见 get_pose_indemind_left.cpp:211。
- 建议先做“角度平滑 + 状态机滞回”：
- 对 tt/ts 做 5 帧中值或 EMA 再分类。
- 进入/退出阈值分离（例如 Pike 进入 ts>160 && tt<130，退出 ts<150 || tt>140，需按数据再标定）。
- 左右腿融合别直接“不同即 Unknown”：现在左右不一致会掉到 Unknown，见 get_pose_indemind_left.cpp:285。可改为置信度加权平均或取高置信侧。
- 建议离线标定阈值：把每帧 tt/ts/label/conf 落盘，用真实标注做网格搜索阈值，尤其针对 pike/tuck 分界。

# 完成优化说明

## 1. 目标与背景

本次优化针对 `yolo_pose_indemind_left` 的三类稳定性问题：

1. RGB 与 Depth 同步存在“取队首 + 清空”导致的时序偏差风险。
2. 人体包围盒渲染直接使用瞬时几何量，画面抖动明显。
3. 姿态分类采用硬阈值，`Pike/Tuck/Straight` 在阈值附近频繁跳变。

目标是在尽量小改动下提升时序一致性、渲染稳定性和分类稳定性，并保持可构建。

## 2. 设计方案与实现理由

### 2.1 RGB-Depth 同步：最新帧策略 + 时间戳最近邻

实现要点：

1. 将 RGB/Depth 缓冲从 `std::queue<cv::Mat>` 改为 `std::deque<TimedFrame>`（包含 `timestamp + frame`）。
2. 主循环每次只取**最新 RGB 帧**（`PopLatestFrame`）。
3. 对该 RGB 时间戳，在当前 Depth 缓冲中按 `abs(depth_ts - rgb_ts)` 选择最近帧（`SelectNearestDepthFrame`）。
4. 清理过旧 depth 历史（>0.35s）并保留最新 depth，避免积压与队首陈旧帧主导。

理由：

1. “最新 RGB + 最近 Depth”比“队首 depth”更符合实时处理目标。
2. 时间戳最近邻直接最小化同步误差，避免简单 FIFO 在双流抖动下错配。
3. 保留小历史窗口能兼顾对齐精度与内存/延迟控制。

### 2.2 Body Box 稳定：中心/方向/尺寸 EMA

实现要点：

1. 新增 `BodyBoxMeasurement` 与 `BodyBoxEmaStabilizer`。
2. 对渲染使用的三类量分别平滑：
   - `center_cam`（中心）
   - `R_body_cam`（方向，线性融合后做正交化）
   - `half_size`（半尺寸）
3. 仅在 `DrawBodyFrameBox` 之前应用平滑，避免侵入骨架求解主路径。
4. 设置复位条件：
   - 连续缺失达到阈值（3 帧）复位；
   - 中心突跳 > 900mm 或体高尺度比异常（>2.2）触发硬复位。

理由：

1. 渲染层平滑即可显著减抖，不改变原始姿态估计数据链。
2. 旋转矩阵平滑后正交化，可抑制数值漂移并保持合法旋转。
3. 复位机制避免跨人切换、遮挡恢复后出现拖影。

### 2.3 姿态分类：状态机 + 迟滞

实现要点：

1. 移除硬阈值 `ClassifyPosture` 直接判定。
2. 新增 `PostureHysteresisClassifier`（持久状态）：
   - 状态：`Unknown / Straight / Pike / Tuck`
   - 进入/退出阈值分离（迟滞带）：
     - `TT`：enter=132°, exit=138°
     - `TS`：tuck enter=132°, tuck exit=138°
   - 连续无效测量达到阈值（6 帧）自动回退 `Unknown`。
3. 在主循环中以 `avg_tt/avg_ts` 更新状态，并将结果写回 `posture_metrics.label` 用于界面显示。

理由：

1. 迟滞机制天然抑制阈值附近抖动。
2. 使用已有平均角度输入，改动范围小、行为可解释。
3. 保留丢失重置逻辑，降低长期误跟踪风险。

### 5.3 验收建议（对应本 step）

1. **同步验证**：观察画面中 `Sync dt` 数值，快速运动时 depth 不应长期滞后 RGB。
2. **包围盒稳定**：在人体轻微抖动/关键点噪声条件下，3D body box 不应高频跳动。
3. **姿态稳定**：在临界动作（接近阈值）时标签不应每帧来回切换。
4. **缺失恢复**：遮挡后恢复时，分类与 body box 应在短时间重新稳定。

## 6. 风险与限制

1. 当前同步为“最近邻”而非严格硬同步，极端丢帧场景仍可能出现短时错配。
2. EMA 参数为经验值，动作风格差异大时可能需要按数据集再调参。
3. 分类器基于 `TT/TS` 两角，复杂躯干姿态仍可能存在边界样本误判。
4. `build/` 目录权限问题并非代码错误，但会影响默认构建流程。

## 7. 后续路线图

1. 引入可配置参数（YAML/CLI）外置同步窗口与 EMA/迟滞阈值。
2. 增加同步统计日志（P50/P95 同步误差）用于离线调优。
3. 对姿态分类加入短窗口一致性投票，进一步降低瞬态抖动。
4. 补充回放数据集与自动回归测试，形成可量化稳定性指标。
