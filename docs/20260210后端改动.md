# BACKEND_REFACTOR_NOTES.md — trampoline_backend 结构改造计划

## 目的
现有后端（如 `get_pose_indemind_left.cpp`）直接：
- 打开 OpenCV 窗口
- 绘制叠加层
- 用鼠标回调选 ROI 四角（床面坐标系）
这些必须迁移到 PySide6 前端。后端改为 headless 服务进程。

## 改动摘要
### 1）拆分核心管线模块（backend/core/）
把单体 cpp 拆分为：
- `camera/`：Indemind RGB + Depth + 时间戳
- `pose/`：YOLO 推理，输出 2D 关键点
- `lift3d/`：深度采样 -> 3D 关键点与有效性
- `bedframe/`：ROI 四点 -> 平面/坐标系 -> cam<->bed 变换
- `metrics/`：角度、R_rel、flip/twist 累计、体态特征
- `events/`：跳次分割（起跳/接床）
- `scoring/`：E/D/ToF/HD/S/P（初期可占位）
- `recording/`：环形缓存、session 输出

### 2）移除后端 UI 与输入依赖
- 删除/禁用：`cv::imshow`、`cv::waitKey`、鼠标回调。
- 允许保留 OpenCV 仅用于图像处理与矩阵运算。

### 3）ROI 选四点机制替换为 IPC
旧：C++ 鼠标点击 4 个角点。
新：UI 在图像上选择 4 点，IPC 下发：
- `SetBedROI(points_img=[(x,y)*4])`
后端计算床面平面/坐标系并返回：
- `bedframe_status`
- 平面方程、原点、变换矩阵（可选）

### 4）新增 IPC 层
新增 `backend/ipc/`：
- PUB：发布帧与遥测
- REP：接收命令（录制、回放、参数设置、ROI、导出请求等）
所有 payload 必须符合 `protocol/schema.json`。

### 5）统一时间戳与 ID（可复现）
每帧输出：
- `frame_id`（递增）
- `ts_ns`（优先用传感器时间，否则用 steady_clock 对齐）
每跳输出：
- `jump_id`（session 内递增）
- 起跳/接床的时间戳

### 6）新增 session 输出目录契约
- `sessions/<date_time>_<athlete?>/`
  - `raw_video.mp4`（可选）
  - `telemetry.jsonl`（逐帧）
  - `kpts2d.csv`, `kpts3d.csv`
  - `events.json`
  - `scores.json`
  - `plots/landing_scatter.png`
  - `report.pdf`

## 受影响最大文件
- `get_pose_indemind_left.cpp`（重构幅度最大）
- `app/depth_region.*`（移除 UI 逻辑，保留数学/检测逻辑）
- 新增 `backend/` 与 `protocol/` 目录
